Admin Queue System - Faction Designer Integration

This prompt documents the faction designer queue processing system.

═══════════════════════════════════════════════════════════════════════════
SIMPLE UPDATE SECTION
═══════════════════════════════════════════════════════════════════════════

The Simple Update section allows designers to swap faction images WITHOUT requiring
a full code rebuild. This section should be populated for every faction with rows
for each swappable image asset.

WHEN TO POPULATE:
- Immediately after a faction's initial build is complete
- Before marking a faction as "built" in the designer

WHAT TO ADD:
For each faction (using faction acronym), add these rows to the Simple Update section:

1. <acr>-glyph.webp           # Faction glyph/symbol
2. <acr>-card.webp            # Faction card image
3. <acr>-spellbooks.webp      # Spellbook reference card
4. <acr>-acolyte.webp         # Acolyte/cultist unit image
5. <acr>-high-priest.webp     # High Priest unit image (if faction has one)
6. <acr>-<unit>.webp          # One row per custom unit

Examples:
- fm-glyph.webp
- fm-card.webp
- fm-spellbooks.webp
- fm-acolyte.webp
- fm-high-priest.webp
- fm-bone-sculptor.webp
- fm-muscle-stitcher.webp
- fm-body-architect.webp
- fm-screaming-wall.webp

For PRM:
- prm-glyph.webp
- prm-card.webp
- prm-spellbooks.webp
- prm-acolyte.webp
- prm-high-priest.webp
- prm-astral-egg.webp
- prm-celestial-fledgling.webp
- prm-ycgnagnnisssz.webp

For DGT:
- dgt-glyph.webp
- dgt-card.webp
- dgt-spellbooks.webp
- dgt-acolyte.webp
- dgt-conquest.webp
- dgt-pestilence.webp
- dgt-war.webp
- dgt-famine.webp
- dgt-death.webp

HOW IT WORKS:
- Designer uploads new image with matching filename
- System detects the file and swaps it in the webp/images folder
- Change appears in game immediately (no rebuild required)
- Assets are deployed via deploy-homebrew-to-vm.sh --assets

IMPORTANT NOTES:
- Simple Update section name may also appear as "Quick Update" in some docs
  (they are THE SAME SECTION)
- This is purely for IMAGE swaps - code changes still require full rebuild
- Unit info SVGs (webp/info/<acr>-<unit>.svg) are NOT in Simple Update
  (those are generated during build and rarely need swapping)

BUILD QUEUE SECTION
═══════════════════════════════════════════════════════════════════════════

When a faction needs to be rebuilt from the current main branch commit (not
just image swaps), add a row here:

FORMAT: MAP-BUILD: <faction-acr> from commit <hash> (Reason)

Entries:
MAP-BUILD: dgt from commit 74fbf916 (Spellbook guidance application: dual-sided spellbooks marked, guidance embedded for Claude)

SPELLBOOK GUIDANCE INTEGRATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The rebuild process automatically includes spellbook guidance for Claude:

1. DETECTION: When a faction has multi-power or multi-sided spellbooks,
   the designer server computes guidance via compute_spellbook_guidance()

2. FLAGS: Spellbooks are marked with:
   - dual=true (for multi-power on side A)
   - dualB=true (for multi-power on side B)
   - twoSided=true (for swappable sides A and B)

3. UI DISPLAY: In the designer, "Guidance for Claude" appears when:
   - At least one spellbook has dual=true OR
   - At least one spellbook has twoSided=true
   Shows both Multi-Power and Multi-Sided guidance sections as needed

4. CLAUDE RECEIVES: When build is submitted:
   - Design JSON includes spellbookGuidance field
   - Claude sees guidance in /designer/api/factions/<fid> endpoint
   - Admin queue agent includes guidance in build prompt
   - Guidance tells Claude about power slots, SBR count, overlay structure

5. FOR DGT SPECIFICALLY:
   - Gods' Scale and similar spellbooks need twoSided=true
   - Ensure no faction exceeds 6 SBR/SB slots on faction card
   - Multi-sided spellbooks = 2 connected SB slots, not 1+1
   - Use Dragon Ascending (one-use) or Daemon Sultans (Doom recharge) code templates

GIT TRACKING - CRITICAL
═══════════════════════════════════════════════════════════════════════════

**ALL changes to designer files and admin.html MUST be committed to git**

After making ANY changes:
1. cd ~/Claude-Projects/cthulhu-wars-tools
2. Run: ~/cthulhu-wars-tools/tickers/git-commit-changes.sh
3. This automatically:
   - Stages all tracked file changes
   - Creates commit with timestamp and change list
   - Provides audit trail of all modifications

Files that MUST be tracked:
- designer/www/app.js
- designer/www/sections.js
- designer/www/rules.js
- designer/www/index.html
- designer/www/inspector.js
- designer/server/designer_server.py
- admin/admin.html

Never deploy without committing first. Git history is the source of truth for
all UI changes and allows rollback if issues occur.
